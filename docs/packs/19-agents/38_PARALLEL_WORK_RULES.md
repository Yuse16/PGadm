# Trabajo paralelo

## Puede trabajarse en paralelo

- UI y pruebas con contrato estable.
- Documentación y seed.
- Módulos sin dependencia directa.
- Auditoría y corrección en ramas distintas.

## No debe trabajarse en paralelo sin coordinación

- Misma tabla.
- Mismo contrato.
- Mismo flujo de estado.
- Mismo componente central.
- Mismo archivo de configuración.
